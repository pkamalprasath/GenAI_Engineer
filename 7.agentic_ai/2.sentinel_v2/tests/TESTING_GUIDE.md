# SENTINEL v2 — Automated Testing Suite

## Overview

The SENTINEL v2 Automated Testing Suite provides comprehensive validation of the compliance investigation platform across three critical dimensions:

1. **E2E Integration Tests** — Multiple compliance frameworks with realistic test cases
2. **Data Flow Validation** — API → Database → Agents → Results pipeline integrity
3. **UI/Dashboard Tests** — Visual validation, accessibility, and functionality

## Quick Start

### Prerequisites

```bash
# Install testing dependencies
pip install httpx sqlalchemy playwright

# Install Playwright browsers (for UI tests)
playwright install chromium
```

### Run All Tests

```bash
# From project root
python tests/run_all_tests.py
```

### Run Individual Test Suites

```bash
# E2E Integration Tests (Compliance Frameworks)
python tests/automated_e2e_tests.py

# Data Flow Validation
python tests/data_flow_validation.py

# UI/Dashboard Tests (requires Streamlit running)
python tests/ui_validation_tests.py
```

## Test Modules

### 1. E2E Integration Tests (`automated_e2e_tests.py`)

**Compliance Frameworks Covered:**

#### Fair Lending (FCRA/FHA)
- **Approved applicant** — Validates compliant processing
- **Denied applicant (race-based pattern)** — Detects potential disparate impact
- **Gender-based pattern** — Identifies ECOA violations

**Test Validation:**
- ✅ Case discovery and identification
- ✅ Compliance verdict accuracy (COMPLIANT/VIOLATION/UNCERTAIN)
- ✅ Regulatory risk assessment (LOW/MEDIUM/HIGH)
- ✅ Report generation and content quality

#### ADA Compliance (Disability Accommodation)
- **Approved with reasonable accommodation** — Validates accessibility compliance
- **Denied without accommodation consideration** — Detects ADA violations

#### Equal Credit Opportunity Act (ECOA)
- **Joint applicant** — Validates joint application handling

### 2. Data Flow Validation (`data_flow_validation.py`)

Validates data integrity through the complete pipeline:
- API Request validation
- Database storage verification
- Agent access and processing
- Result generation and API response

**Test Flows:**

1. **API Connectivity** — Health check and endpoint availability
2. **Database Connectivity** — Direct database access validation
3. **Request → Database** — applicant_data storage verification
4. **Database → Agents** — Graph execution and state management
5. **Agents → Results** — Output generation and API response

**Running Data Flow Tests:**
```bash
python tests/data_flow_validation.py
```

**Test Cases:**
- Approved applicant (normal flow)
- Denied applicant (denial pattern detection)

**Validation Checks:**
```
✓ applicant_data correctly stored in database
✓ Data retrieved by agents during execution
✓ Compliance verdict generated by legal_agent
✓ Regulatory risk assessed by legal_agent
✓ Report generated by report_agent
✓ All results returned via API
```

### 3. UI/Dashboard Tests (`ui_validation_tests.py`)

Validates Streamlit dashboard appearance, functionality, and accessibility.

**Pages Tested:**
- Home page — Layout, header, navigation
- Investigation page — Form inputs, buttons, validation

**Validation Criteria:**

#### Visual/Layout
- ✅ Header/Logo visible and properly positioned
- ✅ Navigation sidebar present and functional
- ✅ Main content area visible
- ✅ Responsive to different screen sizes (mobile/tablet/desktop)

#### Text & Readability
- ✅ Minimum font size (12px) for body text
- ✅ Proper line spacing and letter-spacing
- ✅ Color contrast (WCAG AA standard)
- ✅ Font families are readable (sans-serif preferred)

#### Accessibility
- ✅ ARIA labels present
- ✅ Form inputs properly labeled
- ✅ Buttons have descriptive text
- ✅ Tab navigation order logical
- ✅ Images have alt text

#### Functionality
- ✅ Forms accept input
- ✅ Buttons are clickable
- ✅ Navigation works
- ✅ Data displays correctly

**Running UI Tests:**
```bash
# Requires Streamlit dashboard running on port 8501
python tests/ui_validation_tests.py
```

**Screenshots Generated:**

## Integration with CI/CD

### GitHub Actions Example

```yaml
name: SENTINEL Automated Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      
      - name: Set up Python
        uses: actions/setup-python@v2
        with:
          python-version: '3.11'
      
      - name: Install dependencies
        run: |
          pip install -r requirements.txt
          pip install httpx playwright
          playwright install chromium
      
      - name: Run SENTINEL Tests
        run: python tests/run_all_tests.py
      
      - name: Upload reports
        uses: actions/upload-artifact@v2
        if: always()
        with:
          name: test-reports
          path: sentinel_v2/test_results/
```

## Troubleshooting

### Issue: "API Connection Refused"

**Cause:** SENTINEL API not running on port 8003

**Solution:**
```bash
# Terminal 1: Start API
python -m uvicorn sentinel.api.main:app --port 8003

# Terminal 2: Run tests
python tests/run_all_tests.py
```

### Issue: "Database Connection Error"

**Cause:** PostgreSQL/Supabase unreachable or credentials invalid

**Solution:**
```bash
# Verify DATABASE_URL in .env
cat .env | grep DATABASE_URL

# Test connection directly
psql $DATABASE_URL -c "SELECT 1"
```

### Issue: "Playwright Not Found"

**Cause:** UI testing requires Playwright browsers

**Solution:**
```bash
pip install playwright
playwright install chromium
```

### Issue: "Streamlit Dashboard Not Running"

**Cause:** Dashboard required for UI tests

**Solution:**
```bash
# Terminal: Start Streamlit
streamlit run sentinel/dashboard/app.py --server.port 8501

# Verify: http://localhost:8501
```

## FAQ

**Q: Can I run tests in parallel?**
A: Not currently. Tests share database and API resources. Sequential execution recommended.

**Q: How do I add new test cases?**
A: Edit the `COMPLIANCE_FRAMEWORKS` dictionary in `automated_e2e_tests.py` and add new applicant profiles.

**Q: Do UI tests require the actual Streamlit app?**
A: Yes. Streamlit must be running on port 8501 for UI validation tests.

**Q: How do I filter tests to run only specific frameworks?**
A: Modify the test scripts to filter `ComplianceTestData.get_all_test_cases()` by framework.

**Q: Can I run tests against a staging environment?**
A: Yes. Set `SENTINEL_API_URL` environment variable before running tests.
